# Heller-Einstein

**Status:** v0.1 active cofoundational pillar, sourced from the Einstein-Heller Interface Program v1.7 verified source candidate.

**Purpose:** Heller-Einstein is the third cofoundational repository beside Heller-Godel and Heller-Dirac. It hosts the framework's typed-interface ontology, geometric-realization questions, projection/observation/stochasticity apparatus, and conservative Einstein-Cartan-Dirac physical-action sector.

Where Heller-Godel hosts proof-character / `chi_p` / `zeta_p` structure, and Heller-Dirac hosts spectral / Hopf / modular / field-theoretic apparatus, Heller-Einstein hosts the interface layer that asks how latent geometry, observer-accessible traces, semantic legibility, and projection-induced stochasticity relate without collapsing one layer into another.

The unifying problem is the disciplined version of the Einstein question: apparent probabilistic structure may arise from interface-mediated projection loss rather than from primitive ontological randomness. Heller-Einstein states this through typed interfaces and projection-induced stochasticity, not through a hidden-variable proof or a derivation of quantum mechanics.

## Architectural role

Heller-Einstein is cofoundational with Heller-Godel and Heller-Dirac:

- `SocioProphet/Heller-Godel` owns proof-character data, `chi_p` / `zeta_p` structure, PFK discipline, and framework-core claim grammar.
- `SocioProphet/Heller-Dirac` owns spectral, Hopf, modular, Borel-side, and field-theoretic apparatus.
- `SocioProphet/Heller-Einstein` owns typed interfaces, projection-induced stochasticity, observer-relative semantic legibility, and conservative geometric/physical realization scaffolds.

HE objects may consume HG or HD objects only through typed interfaces. A typed interface must state what is preserved, what is projected away, and what remains deferred. HE does not create proof-grade coherence between HG and HD by prose.
